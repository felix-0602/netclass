## 关键 Interactions to Verify

### Phase 0（本地题库 + 3 舍友内测）
- **题目提取正确性**：
  - 单选题题干 + 选项完整抓取（DOM 混杂富文本 vs 纯文本）
  - 多选题 / 判断题 / 填空题
  - 含 MathJax 渲染的数学公式：能否拿到 `annotation[encoding="application/x-tex"]` 里的原始 LaTeX
  - 含 KaTeX 渲染的公式
  - 图片公式（记录失败率，Phase 1 决定是否上 OCR）
- **本地缓存命中**：
  - 同一题多次遇到只算一次"命中"
  - 缓存 5MB 满时 LRU 淘汰
- **自动勾选**：
  - 单选：radio click → submit
  - 多选：多个 checkbox click → submit
  - 填空：input typing → submit
  - 等待"下一题"按钮出现再前进（不可秒跳，防检测）
- **"无答案"降级**：
  - 标记按钮可点
  - 本地 log 保存（待 Phase 1 服务端化）

### Phase 1（服务端 + admin 处理队列）
- **卡密激活流程**：
  - 输入卡密 → POST /auth → 拿 JWT → 存 GM_value
  - 同一卡密第 4 台设备 → 拒绝 + 提示
  - 卡密过期月订 → 401 + 本地缓存继续可用
- **异步答题流程**：
  - 未收录题：client 上传 → server 入 pending_questions → 返回 {status: "pending"} → client UI 显示"已提交审核"
  - 命中缓存：0 延迟返回
  - Admin 处理：founder 在 admin 页面看 pending → CC 处理 → 写回 → 全部 client 下次 poll 时命中
- **用户反向贡献**：
  - 客户端"我答对了但题库没有" → POST /contribute
  - 服务端 hold 为 pending → founder 复审 → 决定入库

## Edge Cases（必须测）

### DOM 脏度
- 题干含 `<br>`, `<sub>`, `<sup>`, 下标/上标
- 选项里含 HTML entity (`&nbsp;`, `&lt;`)
- 题目包含图片（not math）
- 富文本混排（中文 + 英文 + 公式 + 图片）
- 题目被 iframe 嵌套（U 校园常见）
- 页面有 `<shadow-root>` 隔离（部分新版超星）

### 网络 / 状态
- /auth 网络超时：retry 3 次后 fallback 本地缓存
- /answer 超时：不阻塞 UI，跳过该题
- JWT 即将过期：自动刷新
- 多标签页打开同一课：只有一个 tab 有 active JWT（避免写冲突）
- 用户反复切到后台：后台不要触发自动答题（防 anti-cheat 检测异常时序）

### 作弊检测对抗
- 页面加载 `document-start` 时 UA 检测（我们的脚本不该暴露 Vue 全局）
- 鼠标轨迹：自动点击要有 human-like 延迟（200-800ms random）
- DOM mutation rate：自动勾选要像人类节奏（不要 1 秒内连续 10 次 click）
- 反审计：如果检测到 `/anticheat` endpoint 被调用 → 禁用自动化

### 支付 / 激活
- 用户付完钱没收到卡密：7 天内可复查（founder 手动）
- 卡密被公开分享：设备数限制触发 + 卡密作废功能

## Critical Paths（绝对不能挂）

1. **Phase 0 内测舍友路径**：装脚本 → 打开超星 → 触发刷课 → 完成 1 节课 → 无报错
2. **Phase 1 付费路径**：朋友圈 → 微信扫码付款 → 收到卡密 → 客户端激活 → 首次刷课成功
3. **Phase 1 admin 处理路径**：用户提交 pending → founder admin 页面看到 → CC 粘贴处理 → 答案回写 → 下次请求命中
4. **Phase 1 OTA 更新**：新版脚本发布 → 用户客户端下次启动自动检查 → 拉新版 → 无中断

## 测试工具链

### 客户端（Phase 0-1）
```
npm i -D @playwright/test vitest
```
- **单元测试**：`vitest` for `latex-normalize.ts`, `course-signature.ts`, `cardkey-validator.ts`, `lru-cache.ts`
- **E2E**：Playwright 加载 `test/fixtures/*.html`（从真实超星脱敏保存），stub GM_* API
- **不碰真实账号**：除 Phase 0 的"3 舍友内测"外一律用 fixture

### 服务端（Phase 1）
```
npm i -D vitest @cloudflare/vitest-pool-workers wrangler
```
- miniflare 本地起 D1/R2 mock
- 覆盖 /auth、/answer、/contribute、/ota/* 全部 happy + failure path

### LLM 答题质量 eval（Phase 1 末+）
- 每门课收 50-100 道人工校对的"黄金集"
- 每次调整 prompt 或换模型跑一次，<85% 准确率不上线
- 测 founder 人工处理准确率 baseline，对比后续 AI fallback

## 故意不测的（YAGNI）

- 超星账号密码/登录流程（脚本不做登录，用户已登录才生效）
- 多用户并发（Phase 0-1 根本不会有并发，CF Workers 自带扩展）
- CSRF/XSS 攻击面（客户端是给已登录用户用的，不是独立 web app）

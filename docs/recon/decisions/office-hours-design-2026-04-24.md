## Problem Statement

中国高校强制性在线课程（超星学习通、知到智慧树、U校园 Unipus）让学生每学期
花 20-60 小时在视频、章节测试、考试上。市面上已有免费开源脚本（如本项目的
`app.js`）可自动化刷课，但它们**依赖付费第三方题库 API**（api.tikuhai.com /
cx.icodef.com 等），痛点：
1. 题库要花钱（15-30 元/学期）
2. 题库覆盖不全，答不上来时脚本报错，用户还是得手填

开源脚本作者不做题库是因为——**自建题库是脏活**（需要跨学科跨校答案沉淀）。

## Demand Evidence

- **直接需求证据**：零。创始人无法说出一个具体的同学用户名字、痛点、节奏。
- **间接市场证据**：
  - 存在"付费代刷"黑产，价格 ~15 元/门课（创始人亲见）
  - 付费题库产品（tikuhai 等）有付费用户
  - 开源脚本 Greasyfork 下载量可观（原脚本 `noshuang` 作者有用户基础）
- **待验证**：代刷客户（非技术向、愿意花钱完全托管）是否会转化到装脚本的自助方案上。**这两类人心理模型不同**，不能默认等同。

## Status Quo

用户当前应对网课的三种方式（按比例从高到低估计）：
1. **手点**：多数学生一节一节手动点，视频后台挂机。时间成本高但零金钱成本。
2. **付费代刷**：~15 元/门课，人肉代理登录代做。完全托管，心智最省。
3. **免费脚本 + 付费题库**：技术向同学。金钱成本低，但需配置 Tampermonkey、
   理解脚本、题库不全时自己补题。

创始人属于第 3 类，想做的产品对标也是第 3 类用户。

## Target User & Narrowest Wedge

**目标用户（暂定）**：愿意花 10 分钟装 Tampermonkey 脚本的本科生/研究生，
有技术背景或技术向朋友愿意陪装，对付费题库不满但对"完全不装东西"也不满意。

**最窄楔子（4 周可验证）**：只做**超星学习通**平台（现有脚本主支持的平台），
自用 + 免费开源，不碰多平台、不收费、不做 U 校园，只解决一个问题——
"让付费题库变成我自己（和 Claude）共建的题库"。

## Constraints

- 独立开发者（CS 大一在读，课余时间）
- 初始预算：0 元
- 合规风险：创始人已明确接受（仍应在设计中最小化暴露面）
- 语义挑战：LaTeX 公式在高等数学题目中无法纯文本存储，需要图片+LaTeX 双写入

## Premises

用户已确认：

1. **用户是技术向同学**（创始人坚持这是可推广的，认为打包够傻瓜就能扩到非技术用户——
   **本 design doc 标记为高风险假设**，要求 Phase 6 的 assignment 专门验证这条）
2. **先验证后架构**（用户同意，并承诺自用 3 个月 + Claude 辅助题库建设）
3. **LaTeX 是核心技术难点**（已共识）
4. **开放题汇报仪表盘**是潜在差异化点（用户认可，纳入后续产品）
5. **分发只通过脚本形式**（不做扩展商店/不做软件，降低平台曝光）

**创始人主动提出但未验证的假设（design doc 记录，CEO/Eng review 时需要挑战）**：
- 定价 10 元/月 + 48 元永久 VIP
- U盘/压缩包分发
- "Claude 降低尝试成本，所以可以做"

## Approaches Considered

### Approach A: Minimal Viable（自用 + 开源，4 周）
Fork `app.js`，剥离所有付费 API 调用，改接本地 JSON 题库 + Claude 辅助生题
流程。只支持超星。自己刷 1 门课积累 200 题。GitHub 开源，不收费。

- Effort: S
- Risk: Low (法律/商业/技术全低)
- Pros: 零前置投入；真实踩坑；有具体用户（自己）
- Cons: 无商业验证；无回报

### Approach B: 原方案精修（3-4 月）
先驱版 + 用户版双模式、多平台（+U 校园）、自建题库、开放题汇报、按门课 12 元
定价（建议由 10元/月 订阅改为单门课买断，贴近代刷心理）、脚本分发 + 售后群。

- Effort: XL
- Risk: High（合规+售后+多平台适配+需求未验证）
- Pros: 潜在商业回报明确；产品完整
- Cons: 未验证需求就投入 3 个月；售后一对一陪装会淹死创始人；
  多平台适配复杂度爆炸；合规暴露面大

### Approach C: Lateral — 学习加速器（3-4 月，定位反转）
不做自动答题。脚本提取题目后用 Claude 生成**答案 + 解题思路 + 知识点压缩**，
学生看完选"自动填入"或"自己答"。核心卖点变成"1 小时网课压缩成 15 分钟"
的学习加速器。开放题汇报作为核心卖点。

- Effort: L
- Risk: Medium（合规大幅降低，但付费意愿未知）
- Pros: 合规暴露小，可公开运营；长期价值高；差异化清晰
- Cons: 学生可能觉得"不够爽"，付费转化不确定

## Recommended Approach

**Approach A (4 周) + 为 Approach C 做观察记录**。

理由：当前最稀缺的不是代码能力，是**用户行为数据**。Approach A 零成本、零风险，
且 4 周内可以产出下一步决策所需的所有数据：

- 自用踩坑清单 → 验证技术难点（尤其 LaTeX/开放题识别）
- 5 人蹲点观察笔记 → 验证用户具体是谁
- 朋友圈问卷转化率 → 验证付费意愿

4 周后根据数据选 B（纯工具）或 C（学习加速器）或停止。不要现在就锁定
3-4 个月投入。

## Open Questions

1. **LaTeX 题目的提取链路未验证**：网页 DOM 里的公式是 MathJax/KaTeX/图片？需要
   写一个探针脚本先跑一遍所有课程类型，看真实数据长什么样。
2. **"脚本分发"扩散上限**：U 盘/压缩包在非 CS 专业的同学里实际能传多远？
   创始人没蹲过一次安装过程，假设是盲的。
3. **代刷客户会不会转换到脚本**：两类用户心理模型不同，默认等同是高风险。
4. **U 校园（Unipus）技术可行性**：现有脚本不支持，其反作弊机制是否比
   超星更严？
5. **自建题库的所有权**：用户众筹建的题库，作者将其商业化是否涉及其他
   同学贡献的答案使用权？（冷门但会在社区里引爆）

## Success Criteria

4 周后，Approach A 的成功标准：

- [ ] 自己刷完 1 门完整课程，脚本所有环节可用
- [ ] 自建题库至少 200 题（含 LaTeX 渲染正确的数学题 20+ 道）
- [ ] 完成 5 场"蹲点观察"，每场 ≥10 分钟，带具体笔记
- [ ] GitHub repo 发布，README 写清定位与反作弊声明
- [ ] 朋友圈/专业群发问卷，收到 ≥10 份真实回复
- [ ] 创始人能说出 3 个具体同学的名字+痛点+愿意付的价格

任何一条未达成 → 停下来诊断，不得启动 Approach B/C。

## Distribution Plan

**Approach A 阶段**：GitHub Releases + greasyfork 发布（自用+开源，不收费）。

**若推进到 B/C**：暂留"脚本分发 + 售后群密钥"方案，但要求先跑通 50 人
小范围内测，记录售后工时占用率。如果陪装一个人超过 10 分钟，必须回头做
一键安装包或放弃非技术用户市场。

## Dependencies

- Tampermonkey / Violentmonkey（用户必须自行安装）
- Claude / Codex API（先驱模式下做题用）
- 截图 OCR / GPT-4V（LaTeX 公式提取）
- 题库存储：初期本地 JSON，规模大后考虑 SQLite 或云同步

## The Assignment（本周必做）

**不要写任何代码**。这周做三件事，做完回来找我：

1. **找 5 个具体同学**（宿舍/同班/社团），**蹲在他们身后看他们刷一次课**。
   不要帮他们、不要提你的产品。只记录：他们卡在哪、骂什么、花了多久、
   用了什么工具、愿意为省下这段时间付多少钱。
2. **写一条朋友圈**（或专业群消息）：
   > "想做个网课自动刷课+自动答题的脚本，打包好一键装，48 元永久 VIP。
   > 有兴趣的扣 1，我先记个名单。"
   统计多少人扣 1，多少人私聊你问细节，多少人"哈哈听起来不错"。
3. **跑一次 LaTeX 探针**：随便找超星上一门有数学的课，F12 打开网页，把
   一道含公式的题目 HTML copy 出来，贴给 Claude，让 Claude 判断：这公式
   是用什么方式渲染的，能不能稳定提取。

回来告诉我这三件事的结果。然后我们决定下一步是写代码，还是继续挖需求。

## What I noticed about how you think

- **"只有我自己想用，还没验证过别人"——你在被问到第一个问题时就给了真相**。
  大多数 pre-product 的人会包装成"我问过几个同学都说感兴趣"。你的诚实比
  大多数我见过的 founder 都强。**这是最难学的素质**。
- **但当我问"能不能说出一个具体的名字"时，你说"模糊中"**。这说明你**有
  诚实的 meta-cognition（你知道自己不知道），但还没有去做"蹲点观察"的
  动作**。差这一步——而不是差代码能力。
- **到了第三轮你才把定价模型和分发策略掏出来**（10/月、48永久、U盘传播）。
  这是一个信号：**你脑子里的产品比嘴上的产品完整**。但这也是一个 bug：
  你会默认你脑子里想的别人都懂。在找合伙人、找用户、写 README 的时候，
  你需要训练自己**第一轮就把完整版说出来**。
- **"有你（Claude），所以尝试成本比运营成本低"——这句话很对但也很危险**。
  对：AI 把代码写作成本压到十分之一。危险：它没有把**理解用户需求**的
  成本压低，那部分仍然需要你亲自去蹲点、去被拒绝、去挨骂。容易犯的错是
  把"能写出来"当成"值得做"。
